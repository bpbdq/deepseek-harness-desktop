feat(update): 重做更新界面，两条轨道统一展示与操作

此前「更新」菜单里是两行禁用的版本号（智能体运行时 0.1.5-rc.1 / 外壳 1.0.0），
读起来像选项却点不动；外壳更新则是启动后静默检查并弹对话框，用户既不知道是谁
触发的、也不知道何时检查的。这次都改掉。

现在的入口：菜单栏 → 更新 → 检查更新…（Ctrl+Shift+U），或托盘右键。
窗口立刻打开显示正在检查，两条检查并行、结果各自推送。有可用更新时对应分节
出现操作按钮（运行时=更新并重启，外壳=下载并安装，带百分比进度）。

同时修掉三个之前会让功能失效或误导用户的问题：

1) 文件名不一致导致外壳更新必然 404。electron-builder 生成的 latest.yml 里是
   DeepSeek-Harness-x64.exe（空格转连字符），而 GitHub 上的附件是
   DeepSeek.Harness-x64.exe（空格转点）。按 metadata 下载必然找不到。
   根因是 productName 含空格，故改为 dsh-desktop。这是破坏性变更：安装目录与
   可执行文件名不再含空格，旧版需先卸载，已写进两篇 README 的已知限制。

2) 外壳轨道的已安装版本显示成了运行时版本。原因是 ShellUpdater 被传入了
   runtimeVersion，应使用 app.getVersion()。

3) 无法检查时不显示原因。renderTrack 先正确写入 reason，随后外壳专用分支无条件
   覆盖同一个 note 元素把它清掉，于是用户只看到状态而不知原因。改为仅在无原因时
   补一句通用提示。

结构性改动：新增 panel.ts 抽出发信息面板的公共实现（临时 HTML + sandbox 窗口 +
IPC 推送），project-info 与新 update-window 共用；新增 src/preload/panel.ts 通过
additionalArguments 传频道名（环境变量是进程级的，两个面板同时打开会串）。
启动时的静默 checkShellUpdate 已移除，只保留 autoInstallOnAppQuit。

新增 scripts/cdp-read.mjs 与 cdp-eval.mjs：面板内容用 CDP 读 DOM 验证，比截图
可靠（不受分辨率影响、可断言）。上面第 3 个问题就是靠它们定位的。
